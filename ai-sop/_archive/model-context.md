# model-context.md

> Only used for Moderate and Large/Microservices tiers. Defines how sub-agents relate to the Master Agent and to each other.

## Module Registry
List every module/service and its owning sub-agent:

| Module | Sub-Agent | Module-Agent Context File | Backend Standard File | Frontend Standard File | Codemap Output Folder |
|---|---|---|---|---|---|
| [module-a] | sub-agent-a | module-agent-[module-a].md | backend-standard-[module-a].md | frontend-standard-[module-a].md | codemap-output-[module-a]/ (codemap.json/.md/.html + db-codemap.json/.md) |
| [module-b] | sub-agent-b | module-agent-[module-b].md | backend-standard-[module-b].md | frontend-standard-[module-b].md | codemap-output-[module-b]/ (codemap.json/.md/.html + db-codemap.json/.md) |

*(Large/Microservices: each row typically maps to its own database, so its `codemap-output/` folder's `db-codemap.json` will be specific to that module's database. Moderate: all rows may point to the single shared `codemap-output/` folder.)*
*(Each `codemap-output/` folder is generated by one command: `node codemap-tool/bin/cli.js generate <module-path>`.)*
*(The `module-agent-<module>.md` file is what actually gets attached to bootstrap that sub-agent's own context window — it already links to the standard files and codemap-output folder in its own row, so those don't need separate attaching.)*

## Cross-Module Connectivity (Large/Microservices only)
- Master Agent owns the routing map between sub-agents.
- Define here how a request/data flow crosses module boundaries (e.g. Module A calls Module B's API, Module A's event triggers Module C).
- Any new cross-module dependency must be added to this table before implementation begins.
